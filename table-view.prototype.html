How this would work for you
Example: add Email and Excitement once for Moneo. After interviews, open the table, filter Excitement to High, then filter Email to Is not empty. You have a clear list of people worth contacting again.
01

One project. Two views of the same sessions.

Keep the familiar List, and switch to Table when you want an overview. Each row opens its full session. Edit a cell in the table or the matching field in the session; both show the same value.

02

Add a column once. It appears in every session.

Choose Add column, name it, and choose Text, Email, Number, Select, or Date. For Excitement, choose Select and define Low, Medium, and High. Existing sessions start empty for that new field. No field has to be filled in.

03

Find the sessions you care about.

Sort by a header, or use Sort. Numbers sort numerically, dates chronologically, and Select values follow your option order. Empty values stay at the bottom. Filters can match values or find empty/missing information. Multiple rules mean “match all.”

04

Keep the overview tidy without losing information.

Rename or hide columns from Columns. Hiding changes the view and keeps the data in each session. These project fields are separate from interview questionnaires. Your questions, answers, recordings, and existing sessions stay intact.

05

Export a clear, explicit set.

Selected rows → Export selected. With a filter and no selection → Export results. Otherwise → Export all. The preview lists the included sessions. Existing Markdown, JSON, and ZIP formats would include the project fields, including columns hidden from the table.

The Email and Excitement columns are examples already added in this concept. The proposed real upgrade would not force those columns into every existing project. It would offer them as quick-add presets. View, sorting, filters, and visible columns would be remembered per project.
